# バックエンドテストケース

## 1. この文書の目的

現在実装されているバックエンドテストについて、確認している業務上の条件と期待結果を簡単にまとめる。

対象は主にサービス層であり、リポジトリは Mockito のモックに置き換えている。そのため、実際のデータベース接続や HTTP リクエストではなく、サービスメソッドの判断と返却内容を確認するテストである。

## 2. アプリケーション起動

| ケース | 操作 | 期待結果 |
|---|---|---|
| Springコンテキストの読み込み | テスト用設定でアプリケーションを起動する | Springのコンテキストが例外なく作成される |

対象テスト：`BackendApplicationTests`

## 3. 商品サービス

対象テスト：`ProductServiceTest`

| ケース | 前提・入力 | 操作 | 期待結果 |
|---|---|---|---|
| 商品一覧を取得する | P001とP002の2商品が存在する | `findAll()`を実行する | 2件が返り、商品コードがP001、P002の順に含まれる |
| 存在しない商品を取得する | ID 99の商品が存在しない | `findById(99)`を実行する | `ProductNotFoundException`が発生し、メッセージが`Product not found: 99`になる |
| 商品を登録する | 商品コードP001が未登録 | P001、商品A、単価100.00を登録する | 商品が保存処理へ渡され、レスポンスにP001が返る |
| 重複した商品コードを登録する | 商品コードP001がすでに存在する | P001を登録する | `DuplicateProductCodeException`が発生し、保存処理は実行されない |

## 4. 顧客サービス

対象テスト：`CustomerServiceTest`

| ケース | 前提・入力 | 操作 | 期待結果 |
|---|---|---|---|
| 顧客一覧を取得する | C001とC002の2顧客が存在する | `findAll()`を実行する | 2件が返り、顧客コードがC001、C002の順に含まれる |
| 存在しない顧客を取得する | ID 99の顧客が存在しない | `findById(99)`を実行する | `CustomerNotFoundException`が発生し、メッセージが`Customer not found: 99`になる |
| 顧客を登録する | 顧客コードC001が未登録 | 顧客名、メールアドレス、電話番号を指定して登録する | 入力内容が保存処理へ渡され、レスポンスにC001が返る |
| 重複した顧客コードを登録する | 顧客コードC001がすでに存在する | C001を登録する | `DuplicateCustomerCodeException`が発生し、保存処理は実行されない |

## 5. 受注サービス

対象テスト：`SalesOrderServiceTest`

| ケース | 前提・入力 | 操作 | 期待結果 |
|---|---|---|---|
| 受注を登録する | 有効な顧客C001と単価100.00の有効な商品P001が存在する | P001を3個指定して受注を登録する | 下書き状態で保存され、単価100.00、明細金額300.00、受注合計300.00になる |
| 無効な顧客で受注を登録する | 顧客C001が無効 | 受注を登録する | `InactiveCustomerException`が発生し、受注は保存されない |
| 無効な商品で受注を登録する | 顧客は有効、商品P001が無効 | 受注を登録する | `InactiveProductException`が発生し、受注は保存されない |
| 下書き受注を確定する | 受注が`DRAFT`状態 | `confirm(1)`を実行する | 受注状態が`CONFIRMED`になる |
| 確定済み受注を更新する | 受注が`CONFIRMED`状態 | `update(1, request)`を実行する | `SalesOrderNotEditableException`が発生し、顧客・商品の検索も実行されない |
| 確定済み受注を削除する | 受注が`CONFIRMED`状態 | `delete(1)`を実行する | `SalesOrderNotDeletableException`が発生し、削除処理は実行されない |

## 6. 現在のテストで確認していない範囲

現在のテストには、次の内容はまだ含まれていない。

- 商品・顧客の更新と削除
- 受注一覧と受注詳細の取得
- 下書き受注の正常な更新と削除
- 受注キャンセルの正常系・異常系
- 顧客コードまたは商品コードが存在しない場合
- 明細が0件の場合や数量が不正な場合
- ControllerのHTTPステータスとJSON形式
- Bean Validationによる入力チェック
- PostgreSQLを利用したリポジトリ・マイグレーションの確認

これらは、サービス機能が増えた段階で単体テストまたは結合テストとして追加する。

## 7. テスト実行方法

`backend`ディレクトリで次を実行する。

```powershell
./gradlew test
```

テスト結果の詳細は次のHTMLレポートで確認できる。

```text
backend/build/reports/tests/test/index.html
```
